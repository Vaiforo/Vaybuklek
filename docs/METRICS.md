# Метрики проекта «Дирижёр»

Метрики разделены на две группы: продуктовые показывают пользу для команды и менеджера, технические — устойчивость и качество реализации.

---

## Продуктовые метрики

| Метрика | Что показывает | Формула |
|---|---|---|
| **Task Capture Rate** | Насколько полно бот находит реальные задачи в чатах и встречах | `найденные ботом задачи / все реальные задачи` |
| **Task Precision** | Насколько мало ложных задач предлагает бот | `подтверждённые задачи / все предложенные задачи` |
| **Deadline Recognition Rate** | Как часто бот извлекает срок выполнения | `задачи с дедлайном / все созданные задачи` |
| **Assignee Recognition Rate** | Как часто бот определяет ответственного | `задачи с ответственным / все созданные задачи` |
| **Confirmation Effort** | Сколько ручных действий требуется человеку | `клики и сообщения подтверждения / созданные задачи` |
| **Auto-mode Share** | Насколько команда доверяет автоматике | `задачи, созданные в auto-mode / все созданные задачи` |
| **Duplicate Prevention Rate** | Сколько повторных карточек удалось не создать | `распознанные дубли / все повторные формулировки` |
| **Board Freshness** | Как быстро канбан отражает договорённости | `время от сообщения или встречи до карточки/статуса` |
| **Reminder Effectiveness** | Помогают ли напоминания обновлять задачи | `задачи, обновлённые после напоминания / все напомненные задачи` |
| **Report Compliance** | Дисциплина вечерних отчётов | `отчитавшиеся участники / участники с открытыми задачами` |
| **Workload Risk Alerts** | Насколько часто бот видит риск перегруза | `предупреждения о перегрузе / активные исполнители` |
| **PM Time Saved** | Экономия времени project-менеджера | `ручное время до внедрения − ручное время после внедрения` |
| **Personal Cabinet Usage** | Пользуются ли личным кабинетом | `активные пользователи / участники команды` |
| **Knowledge Base Contribution** | Пополняет ли команда базу знаний | `новые записи базы знаний / неделю` |
| **Gamification Engagement** | Работает ли RPG-мотивация | `профили с XP и ачивками / активные участники` |

### Минимальный набор для презентации

- **Task Capture Rate** — бот действительно находит задачи.
- **Task Precision** — бот не засоряет доску мусором.
- **Confirmation Effort** — взаимодействие сводится к подтверждениям.
- **Board Freshness** — договорённости быстро становятся карточками.
- **Report Compliance** — команда чаще отчитывается без ручного пинга.

## Технические метрики

| Метрика | Что показывает | Формула или способ измерения |
|---|---|---|
| **End-to-End Latency** | Скорость всей цепочки | `время ответа/карточки − время входящего события` |
| **LLM Valid JSON Rate** | Стабильность структурированного ответа LLM | `валидные JSON-ответы / все вызовы LLM` |
| **Low Confidence Rate** | Как часто бот уходит в уточнение | `кандидаты с низкой confidence / все кандидаты` |
| **False Positive Rate** | Как часто обычный шум принят за задачу | `отклонённые предложения / все предложения бота` |
| **Dedup Accuracy** | Качество поиска повторных задач | `реальные дубли среди найденных / все найденные дубли` |
| **YouGile API Success Rate** | Стабильность интеграции с канбаном | `успешные операции YouGile / все операции YouGile` |
| **Telegram Delivery Rate** | Надёжность отправки сообщений | `успешно отправленные сообщения / все попытки отправки` |
| **Reminder Job Success Rate** | Надёжность фоновых задач | `успешные запуски jobs / все запуски jobs` |
| **Health/Uptime** | Доступность ядра | `/health` отвечает `status=ok` |
| **STT WER** | Качество распознавания речи | `Word Error Rate` на тестовых аудио |
| **Speaker Attribution Accuracy** | Качество диаризации встреч | `правильно определённые сегменты / все сегменты` |
| **Fallback Rate** | Частота деградации во fallback/mock | `fallback-срабатывания / обращения к внешним сервисам` |
| **Auth Error Rate** | Проблемы авторизации API | `401 responses / все API-запросы` |
| **Test Pass Rate** | Стабильность ядра | `пройденные тесты / все тесты` |
| **DM Delivery Fallback Rate** | Как часто личное уведомление падает обратно в общий чат | `уведомления в общий чат из-за отсутствия DM / все персональные уведомления` |

### Целевые значения для MVP

| Метрика | Ориентир |
|---|---:|
| End-to-End Latency для текста | `p50 < 3 сек`, `p95 < 10 сек` |
| LLM Valid JSON Rate | `95%+` |
| Task Precision | `80%+` |
| False Positive Rate | `< 15–20%` |
| YouGile API Success Rate | `99%` в стабильном окружении |
| `/health` latency | `< 500 мс` |
| STT WER на чистом звуке | `< 20–30%` |

## Как собирать метрики в прототипе

1. Логировать каждое входящее событие: источник, чат, время получения.
2. Логировать результат извлечения: `outcome`, `confidence`, наличие дедлайна и исполнителя.
3. Логировать решение пользователя: подтвердил, поправил, отклонил, включил auto-mode.
4. Логировать операции с YouGile: тип операции, статус, длительность, ошибку.
5. Логировать фоновые jobs: время запуска, число напоминаний, число чатов сверки.
6. Для пилота раз в день строить сводку по задачам, отчётам и ошибкам.
