# 🎼 Дирижёр

**Дирижёр** — прототип Telegram-бота, который берёт на себя часть работы project-менеджера: читает командный чат, обрабатывает встречи, извлекает задачи, ведёт канбан-доску YouGile, напоминает о сроках и сверяет вечерние отчёты.

Главный принцип продукта: бот не заменяет команду и менеджера, а синхронизирует их работу. Человек по умолчанию только подтверждает, правит или отклоняет найденные задачи.

---

## Возможности

### Обязательный MVP

- **Интеграция с Telegram.** Бот добавляется в командный чат, читает обычные сообщения и находит задачи, дедлайны и ответственных.
- **Извлечение задач через LLM.** Ответ LLM приводится к строгой JSON-схеме с полем `confidence`; при низкой уверенности бот задаёт уточняющий вопрос.
- **Канбан-доска YouGile.** Система создаёт карточки, назначает исполнителей, двигает задачи по статусам и закрывает их.
- **Проактивные напоминания.** Планировщик напоминает о близких и просроченных дедлайнах.
- **Вечерняя сверка.** Бот принимает отчёты, обновляет статусы задач и отмечает участников, которые не отчитались.
- **Минимальное ручное управление.** Режим по умолчанию — подтверждение задачи кнопкой; для доверенных чатов доступен `auto-mode`.

### Усиления реализации

- **Mock-first режим.** Без ключей Telegram, LLM, YouGile и аудио система не падает, а переходит в демонстрационный режим.
- **Дедупликация задач.** Повторные формулировки объединяются с уже созданными задачами через ChromaDB или лексический fallback.
- **Память проекта.** Бот ведёт человекочитаемый Markdown-снимок команды, открытых задач и последних решений.
- **Контекст переписки.** В LLM передаётся окно последних сообщений, чтобы команды вроде «поставь задачу» работали по предыдущему обсуждению.
- **Голос и встречи.** Текстовые транскрипты обрабатываются сразу; реальное аудио поддерживается через пайплайн `noisereduce → pyannote → Whisper` при включении аудио-зависимостей.
- **Контроль нагрузки.** Если у исполнителя слишком много открытых задач или дедлайнов в один день, бот предупреждает чат.
- **Трекинг скорости и качества.** Личный кабинет показывает закрытые задачи, просрочки, средний цикл выполнения и долю задач, закрытых в срок.
- **Личный кабинет.** В Telegram доступны профиль, личные задачи, заметки, XP и ачивки.
- **База знаний команды.** Команда может сохранять и искать короткие знания прямо через бот-команды.
- **Личные сообщения.** Если участник написал боту в личку, подробные напоминания и сводки приходят туда; иначе бот продолжает писать в общий чат.

## Архитектура

Система разделена на четыре слоя.

```text
Telegram / голос / встречи / cron
        │
        ▼
n8n: webhook и расписания
        │
        ▼
FastAPI + aiogram + TaskService
        │
        ├─ LLM extraction: строгий JSON + confidence
        ├─ память проекта и дедупликация
        ├─ reconciliation: отчёты и статусы
        └─ scheduler: напоминания и вечерняя сверка
        │
        ▼
YouGile + Telegram-ответы
```

### Структура проекта

```text
src/dirizher/
  api/              FastAPI-эндпоинты для n8n и health-check
  audio/            распознавание речи, диаризация и реестр голосов
  bot/              Telegram-бот на aiogram: команды, кнопки, сценарии
  cli/              консольное демо, обработка встреч, диагностика ключей
  domain/           доменные модели и перечисления
  integrations/     клиенты внешних сервисов, сейчас YouGile
  llm/              провайдеры LLM, промпт, парсинг и предфильтр
  memory/           дедупликация и Markdown-снимок проекта
  scheduler/        фоновые задания
  services/         бизнес-логика задач, встреч и вечерней сверки
n8n/                импортируемый workflow оркестрации
logs/ .data/        локальные runtime-артефакты, не должны попадать в git
```

## Быстрый старт

### Установка

```bash
python -m venv .venv
source .venv/bin/activate          # Linux / macOS
# .venv\Scripts\activate          # Windows PowerShell
python -m pip install -e .
```

Для разработки и тестов:

```bash
python -m pip install -e ".[dev]"
```

### Демо без внешних ключей

```bash
python -m dirizher.cli.simulator
```

Пример сценария:

```text
you> Максим, сделай авторизацию к четвергу
бот> нашёл задачу и предложил создать карточку
you> y
бот> карточка создана на mock-доске
```

### Обработка встречи из транскрипта

```bash
python -m dirizher.cli.meeting path/to/transcript.txt
```

Формат транскрипта:

```text
Анна: Нужно подготовить демо к пятнице.
Максим: Я доделаю авторизацию завтра.
```

## Запуск Telegram-бота

1. Скопируйте пример настроек:

   ```bash
   cp .env.example .env
   ```

2. Заполните минимум `DIRIZHER_TELEGRAM__BOT_TOKEN`.
3. Запустите приложение:

   ```bash
   python -m dirizher.main
   ```

Если ключи LLM, YouGile или аудио не заданы, соответствующие компоненты работают в mock-режиме.

## Основные настройки

| Переменная | Назначение |
|---|---|
| `DIRIZHER_TELEGRAM__BOT_TOKEN` | токен Telegram-бота |
| `DIRIZHER_TELEGRAM__MODE` | режим Telegram: `polling` или `webhook` |
| `DIRIZHER_LLM__PROVIDER` | провайдер LLM: `mock`, `groq`, `gigachat` |
| `DIRIZHER_LLM__CONFIDENCE_THRESHOLD` | порог уверенности для создания задачи |
| `DIRIZHER_YOUGILE__API_KEY` | API-ключ YouGile |
| `DIRIZHER_YOUGILE__COLUMN_TODO` | ID колонки «К выполнению» |
| `DIRIZHER_YOUGILE__COLUMN_IN_PROGRESS` | ID колонки «В работе» |
| `DIRIZHER_YOUGILE__COLUMN_DONE` | ID колонки «Готово» |
| `DIRIZHER_MEMORY__BACKEND` | backend дедупликации: `lexical` или `chroma` |
| `DIRIZHER_AUDIO__ENABLED` | включение реального аудио-пайплайна |
| `DIRIZHER_AUDIO__MEETING_SOURCE` | дефолтный источник звука встреч: `telemost`, `loopback` или `extension` |
| `DIRIZHER_AUDIO__MEETING_SILENCE_SECONDS` | авто-стоп записи после стольких секунд тишины (по умолчанию 180) |
| `DIRIZHER_API__HOST` / `DIRIZHER_API__PORT` | адрес HTTP-API (приём аудио из расширения, n8n) |
| `DIRIZHER_API__SHARED_SECRET` | общий секрет для n8n и расширения (заголовок `X-Dirizher-Token`) |

## Команды бота

| Команда | Описание |

| `/kb` | последние записи базы знаний |

| `/kb find запрос` | найти запись в базе знаний |
| `/report <текст>` | отправить вечерний отчёт и обновить статусы |

| `/remind` | вручную запустить проверку дедлайнов |

## Захват звука встреч

Бот умеет получать звук созвона тремя способами. Выбирается на каждый чат
командой `/meeting_source`; глобальный дефолт — `DIRIZHER_AUDIO__MEETING_SOURCE`
в `.env`. Во всех режимах дальше идёт один и тот же конвейер: распознавание →
диаризация → саммари → задачи на доску с кнопками подтверждения.

| Режим | Кто пишет звук | Когда удобно | Что нужно |
|---|---|---|---|
| `telemost` | **бот сам заходит** в звонок по ссылке (браузер Playwright) и пишет его звук | на машине никого нет, есть ссылка Телемоста | `pip install playwright` + `playwright install chromium` |
| `loopback` | пишется **системный звук** машины, которая уже в звонке | вы сами в звонке на этом ПК | `pip install soundcard` (входит в extra `audio`) |
| `extension` | **браузерное расширение** захватывает звук вкладки созвона и шлёт боту | созвон в браузере (Телемост / Meet / Zoom-web) на другом устройстве | поставить расширение (ниже) |

Переключение:

```text
/meeting_source            # показать текущий режим
/meeting_source telemost   # бот входит в звонок сам
/meeting_source loopback   # писать системный звук машины
/meeting_source extension  # звук шлёт браузерное расширение
```

Запись (в любом режиме) останавливается сама по тишине (~3 мин,
`DIRIZHER_AUDIO__MEETING_SILENCE_SECONDS`) или командой `/meeting_stop`.

### Режим `telemost` / `loopback`

Киньте в чат ссылку `telemost.yandex.ru/...`:

- в режиме `telemost` бот откроет браузер, представится именем
  `DIRIZHER_AUDIO__TELEMOST_JOIN_NAME` и зайдёт в звонок (на живом созвоне может
  потребоваться вручную дожать вход/комнату ожидания);
- в режиме `loopback` бот начнёт писать системный звук — просто подключитесь к
  звонку на этой же машине.

### Режим `extension` — браузерное расширение

Расширение лежит в папке [`extension/`](extension/) (Chrome / Edge, Manifest V3).
Подробности — в [`extension/README.md`](extension/README.md).

**1. Настройте бота.** Задайте в `.env` секрет (без него эндпоинт приёма аудио
открыт) и при необходимости адрес API:

```env
DIRIZHER_API__SHARED_SECRET=любая-длинная-строка
DIRIZHER_API__HOST=0.0.0.0
DIRIZHER_API__PORT=8080
```

Запустите бота (`python -m dirizher.main`) — он поднимет HTTP-API на этом порту.

**2. Поставьте расширение.** Откройте `chrome://extensions` → включите «Режим
разработчика» → «Загрузить распакованное» → выберите папку `extension/`.

**3. Свяжите чат и расширение.** В нужном Telegram-чате отправьте
`/meeting_capture`. Бот переключит чат в режим `extension` и пришлёт готовый
конфиг:

```json
{ "api_base": "http://localhost:8080", "chat_id": -100123, "token": "ваш-секрет" }
```

Откройте настройки расширения (попап → ⚙️), вставьте эти три поля и нажмите
«Проверить связь».

**4. Пользуйтесь.** Киньте в чат ссылку Телемоста — расширение **само начнёт
запись** активной вкладки созвона (опрашивает бота раз в ~4 c). По тишине ~3 мин
или по `/meeting_stop` запись остановится и улетит боту.

> ⚠️ Chrome иногда требует «жест пользователя» для захвата вкладки. Если
> автозапуск заблокирован, иконка расширения подсветится значком **▶** — тогда
> один раз нажмите «● Записать» в попапе (дальше авто-стоп работает сам).

## n8n

В каталоге `n8n/` лежит workflow `dirizher-orchestration.json`.

Он выполняет три функции:

1. принимает Telegram webhook и отправляет update в `POST /ingest/telegram`;
2. запускает регулярные напоминания через `POST /jobs/reminders`;
3. запускает вечернюю сверку через `POST /jobs/evening-reconcile`.

HTTP API защищается заголовком `X-Dirizher-Token`, если задан `DIRIZHER_API__SHARED_SECRET`.

## Метрики качества

Подробный список метрик находится в [`docs/METRICS.md`](docs/METRICS.md).

Ключевые продуктовые метрики:

- доля найденных задач в чате и встречах;
- точность предложенных задач;
- количество ручных действий на одну карточку;
- скорость попадания задачи на доску;
- доля участников, которые отчитались вечером;
- средний цикл выполнения задач и доля закрытых в срок;
- активность личного кабинета, заметок, базы знаний и ачивок.

Ключевые технические метрики:

- задержка от сообщения до карточки;
- доля валидных JSON-ответов LLM;
- доля низкой уверенности `confidence < threshold`;
- качество дедупликации;
- успешность операций YouGile API;
- доступность `/health` и фоновых jobs;
- успешность личных уведомлений и fallback в общий чат.

## Ограничения текущего прототипа

- `TaskRepository` хранит задачи в памяти процесса; для production нужна БД.
- Звук встреч пишется тремя способами (`/meeting_source`, см. раздел «Захват звука встреч»): `telemost` — бот сам входит в звонок по ссылке через браузер Playwright (нужен `pip install playwright` + `playwright install chromium`); `loopback` — захват системного звука машины, которая уже в звонке; `extension` — браузерное расширение захватывает звук вкладки созвона и шлёт боту. У Телемоста нет публичного API входа, поэтому автоподключение идёт через браузер и на живом созвоне может требовать ручного дожатия (логин/комната ожидания). В режиме `extension` Chrome может требовать жест пользователя для захвата вкладки — тогда запись запускается одним кликом в попапе расширения.
- Mock-LLM покрывает типовые фразы, но на сложной живой речи уступает Groq/GigaChat.
- Семантическая дедупликация требует `chromadb`; по умолчанию используется сетевой-независимый лексический backend.
